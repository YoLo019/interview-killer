# Answer Rubric

Use these standards when writing or reviewing answers.

## General Rules

- Sound like a candidate speaking in an interview.
- Prefer concrete tradeoffs over generic praise.
- Tie answers back to evidence from the resume and projects when possible.
- Do not overclaim implementation details that are not grounded.

## Project-Backed Answers

Must try to include:

- what the project was solving
- what the candidate owned
- the key technical design
- one concrete tradeoff
- one concrete difficulty or risk

## Principles and Engineering Answers

Must try to include:

- the core concept
- why it matters in practice
- a tradeoff or boundary
- how it maps to the candidate's project when possible

## Fundamentals Answers

Must avoid textbook dumping.  
Answer in this order when possible:

1. direct definition
2. why it matters
3. practical tradeoff
4. project connection

## Hot AI and Agent Answers

Prefer this pattern:

1. state the scenario
2. list the main options
3. explain the selection criteria
4. explain the current choice
5. admit drawbacks
6. say when you would switch

## Uncertainty Handling

If a detail is not grounded:

- say it is not fully confirmed
- give a safe framing
- avoid pretending the user implemented something they did not
